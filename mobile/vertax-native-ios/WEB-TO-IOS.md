# Web to iPhone

Snapshot based on the current web implementation in `js/handlers.js`, `docs/product.md`, `lib/compatibility-analysis.js` and the public API routes. The iPhone app keeps its own local data model and uses the existing backend.

| Web capability | iPhone today | Decision for release |
| --- | --- | --- |
| Crate and metadata | Local crate, public Discogs vinyl import, edition search by title/catalog number, local edits and real tracklists. Results show catalog number, country, year, label and format when present. Track and record entries have separate identity. | Verify large live Discogs imports and confirm provider rights. |
| Set builder | One manual selection across record and track views. Selecting a release uses its saved tracks in side order, or the release as a physical cue when no tracks are saved. Search only filters the picker and sorting only reorders the draft. Separate genre/duration generation previews a new draft from crate tracks or the current draft. Active drafts can be exported as TXT to Files or shared via the system share sheet. | Both platforms estimate play time using half the track length. The web uses the estimate to guide track count; iOS previews an ordered selection using known durations. Tracks with unknown duration are counted and excluded from targeted generation, not manual selection. Tracks with a duration but missing BPM or Camelot may still be included. Genre targeting uses a saved track genre or its parent release when the track genre is unknown. Named sets are unchanged by generation. |
| Live Mode | Independent local Set and Free queues restore the played position after pause or app restart. Cue order stays separate from the draft; suggested additions extend only the live set. The clock keeps counting while an active app session is in the background and stops on explicit pause or completion. Ending a session clears only its progress. | Local cue tracker for physical records, not an audio player. Live progress is not part of exported backups. If a saved cue no longer exists in the crate, it is skipped without counting it as played. Verify interruptions on physical hardware before release. |
| Will this release fit? | Check a track or a specific Discogs vinyl pressing. Whole-release scoring uses local BPM, Camelot and recognized genre families. Results separate coverage, strong pairs, tracks without pairs and tracks missing data. Incomplete tracks can be corrected for the current analysis and rescored locally. On an unavailable tracklist, the app can compare the pressing's already-saved tracks and labels this as a subset. | Analysis corrections are session-only and do not update the crate, the provider, or backups. The full Discogs tracklist and automatic enrichment require a connection. No native purchase score, marketplace price or AI verdict. Public enrichment uses batches of up to six tracks and keeps partial results if interrupted. |
| Collection Gaps | Counts actual track entries. Shows coverage, occupied tempo bands, Camelot heatmap and local digging targets around populated keys and isolated tempo gaps. Key targets name a real track in the crate to try against. Small collections and sparse metadata are gated. | No ranked new-release candidates. The public catalog link opens an unfiltered catalog, and the web candidates API is not called. |
| Metadata sources | Native online BPM/Key uses the existing Beatport lookup. Imported releases have no assumed BPM or Camelot. Local edits are kept during reimport. The BPM editor offers doubling and rounded halving only when the result stays within 40–250 BPM. | Reuse the shared catalog/cache and verified fallback providers before claiming source parity. Include provenance per field when a fallback supplies only BPM or key. |
| Backup and local data | Settings exports a versioned iPhone backup with entries, named sets, draft order and wishlist. Restore merges native JSON and both web v1 export shapes, reuses the current library where possible and recovers missing set tracks from snapshots. Web track durations import from colon-separated time or seconds (JSON number or numeric string). | Web settings, images and source-specific fields without an iOS equivalent are excluded. Backups with neither a track reference nor a usable snapshot cannot restore that set position. Migration fixtures derive from the web writer. A real user backup and very large live Discogs imports still need coverage. |
| Catalog, AI and community | Native app uses Discogs links for imported metadata and can open the public web catalog from Gaps. | No in-app catalog feed, AI commentary or shared recommendations. SEO stays on the web. |

## Server collection index

The native app sends explicit metadata lookups, Discogs search terms, public Discogs usernames and release IDs. Release analysis uses read-only GET requests to `/api/discogs` and `/api/beatport-lookup`, with lookup terms taken from the public pressing. The score, gap targets, personal library and local corrections stay on the device. No collection hash or user ID is sent by these flows. The web endpoints `/api/collection-index`, `/api/analyze-release` and `/api/candidates` use a temporary collection index with a 30-day sliding TTL; the iPhone app does not call them. Any future collection transfer needs an explicit, informed opt-in and updated privacy disclosures first.
